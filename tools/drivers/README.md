# tools/drivers — Windows 驱动绑定的失败记录

这个目录保存的是**所有失败的尝试**，不是可用方案。

**可用方案只有一个：用 [Zadig](https://zadig.akeo.ie/) 手动点三下。** 见 `../edl/README.md`。

保留这些文件是因为：如果你也在纠结"为什么 pnputil 装了但 libusb 还是看不见设备"，这里能省你半天。

## 文件

| 文件 | 说明 |
|---|---|
| `qcusb9008_winusb.inf` | 自定义 INF（带 CatalogFile，缺签名文件） |
| `install_winusb2.ps1` | 用 `SetupDiSetDeviceInstallParams` 限定 DriverPath 后强制安装 |
| `force_winusb.ps1` | 用 `DiInstallDevice` + `INSTALLFLAG_FORCE` 强绑 inbox `winusb.inf` |

## 尝试记录与结果

目标设备：`USB\VID_05C6&PID_9008`（Qualcomm EDL 9008）
初始状态：`CM_PROB_FAILED_INSTALL`（驱动安装失败），libusb 看不见设备

| # | 方法 | 结果 |
|---|---|---|
| 1 | 自写 INF（带 `CatalogFile`）+ `pnputil /add-driver /install` | ❌ "第三方 INF 不包含数字签名信息" |
| 2 | 自写 INF（去掉 `CatalogFile`）+ `pnputil` | ❌ 同上 |
| 3 | Windows Update 驱动搜索（`Microsoft.Update.Session`） | ❌ `HRESULT 0x80248014` |
| 4 | `DiInstallDevice` + `INSTALLFLAG_FORCE` 绑 `winusb.inf` | ⚠️ 状态变 `OK`，但**无 `Service` 项** |
| 5 | 同上，但先 `SetupDiSetDeviceInstallParams(DriverPath=winusb.inf)` | ❌ `SetupDiEnumDriverInfo` 返回空（硬件 ID 不匹配） |
| 6 | 用已签名的 `android_winusb.inf` 作为 DriverPath | ❌ 只有 `VID_18D1` 条目，枚举为空 |
| 7 | `pnputil /restart-device` | ⚠️ 能重启节点，但**会把已有驱动绑定搞丢** |
| 8 | `pnputil /disable-device` + `/enable-device` | ❌ 对 `CM_PROB_FAILED_START` 无效 |
| 9 | 重启父 USB hub | ❌ 对"描述符请求失败"态无效 |
| 10 | 从 Zadig 提取内嵌驱动 | ❌ Zadig 是 **UPX 压缩**的，资源目录（`.rsrc`）里没有驱动文件 |
| 11 | **Zadig GUI 手动安装** | ✅ **成功** |

## 关键教训

### `DiInstallDevice` 返回成功 ≠ 驱动绑上了

第 4 条特别容易骗人：

```powershell
[SetupApi]::DiInstallDevice(...)      # 返回 True
# 设备状态: Error → OK
```

看着像搞定了。但一查注册表：

```powershell
$k = 'HKLM:\SYSTEM\CurrentControlSet\Enum\USB\VID_05C6&PID_9008\<instance>'
(Get-ItemProperty -Path $k -Name Service -ErrorAction SilentlyContinue).Service
# 空
```

**没有 `Service` 项 = 驱动没绑上**，只是把错误码清了。libusb 当然还是看不见。

**验证驱动是否真的绑上，看 `Service` 项，别看设备管理器图标。**

### 微软 inbox 的 `winusb.inf` 只匹配两个 ID

```
[Generic.Section.NTamd64]
%USB\MS_COMP_WINUSB.DeviceDesc% = WINUSB, USB\MS_COMP_WINUSB
%USB\MS_COMP_ADB.DeviceDesc%    = ADB,    USB\Class_ff&SubClass_42&Prot_01
```

EDL 设备的 compatible ID 是 `USB\COMPAT_VID_05C6&Class_FF&SubClass_FF&Prot_10`，
两个都不匹配，所以 inbox 驱动永远不会自动绑上。

自定义 INF 能匹配，但 x64 需要签名。

### Zadig 为什么能行

libwdi（Zadig 的底层库）会**现场生成**针对具体 VID/PID 的 INF，配上它自带的微软交叉签名 `.cat`。
安装后注册表里能看到：

```
Signer Name: USB\VID_05C6&PID_9008 (libwdi autogenerated)
Service:     WinUSB
```

## 如果你要自己造 INF

需要满足三个条件（缺一不可）：

1. INF 里 `[Manufacturer]` 的 Models 节包含目标硬件 ID
2. `Include = winusb.inf` + `Needs = WINUSB.NT` 来引用 inbox 的 WinUSB 服务
3. **有有效的 `.cat` 目录文件签名**（x64 强制要求）

第 3 条是自己造 INF 过不去的坎。没有 Windows SDK（`inf2cat` / `signtool`）和代码签名证书的话，
直接上 Zadig。

## 卸载 / 恢复

如果想恢复成"未知设备"状态：

```powershell
pnputil /delete-driver oemXX.inf /uninstall /force
# oemXX 用 pnputil /enum-drivers 查，找 Provider 为 libwdi 的那个
```

或者设备管理器里右键 → 卸载设备 → 勾选"删除驱动程序"。
